ARQUITETURA & PRODUTOS

Componentes desacoplados. Integridade contínua.

A Tessera é um conjunto de ferramentas modulares de engenharia de dados projetadas para operar independentemente ou como uma malha coordenada de automação não-produtiva.

1. Tessera Discovery

Solicitar Documentação →

Framework Go · Biblioteca Pura sem I/O · Recall-First

O Discovery é uma biblioteca Go reutilizável e desacoplada, projetada sem I/O direto: ela consome metadados e amostras fornecidos pelo chamador e devolve um inventário auditável com domínios de dados, algoritmos de mascaramento recomendados e grau de confiança.

// FLUXO DE EXECUÇÃO DO FRAMEWORK DISCOVERY (ZERO DIRECT I/O) // deslize para ver → 
Aplicação Consumidora (Web / CLI / K8s Job)
        │
        ├──> Metadados de Esquema (colunas, tipos, constraints)
        ├──> Amostras de Linhas (valores em texto / JSON estruturado)
        │
        ▼
[ Tessera Discovery Engine ]
   ├── Classificadores de Caminho (Regex sobre Path / Coluna)
   ├── Classificadores de Valor (Regex, Validador Luhn, Checksums)
   ├── Dicionários & Entropia de Shannon (Alta aleatoriedade)
   └── Avaliação Recall-First (Matches ambíguos → needs_review)
        │
        ▼
Inventário Estruturado de Classificação (Auditável & Determinístico)
  Ex: customers.cpf  → Domínio: BR_CPF  → Algoritmo: CPF Masking (Confiança: 1.0)
  Ex: billing.num_cc → Domínio: CC_PAN  → Algoritmo: Luhn FPE (Confiança: 0.98)
Classificadores Plugáveis Type, Path (regex), Data (regex), Luhn (cartões), Dicionários de domínio e Entropia de Shannon.
Recall-First Strategy Prioridade matemática para reduzir falsos negativos; dados incertos são demarcados como needs_review.
PATH e DATA Independentes Detecta campos sensíveis mesmo em bancos legados com nomes ofuscados (ex: tabelas SAP FLD_019, ZZ_ATTR).
Modelo Relacional + JSON Tratamento unificado por caminho (path[]), processando colunas relacionais e nós JSON sem duplicar código.

2. Tessera Masking

Solicitar Documentação →

Framework Go · Criptografia Determinística Key-Driven · FF1 NIST SP 800-38G

O determinismo matemático é o pilar da integridade relacional da Tessera: mesma chave + mesma config + mesmo input = saída byte-idêntica. Ao aplicar o mascaramento em repouso (Static Masking), chaves estrangeiras e identificadores entre diferentes microsserviços continuam se relacionando perfeitamente sem nunca revelar dados brutos.

// FLUXO DE MASCARAMENTO DETERMINÍSTICO (FF1 NIST SP 800-38G) // deslize para ver → 
Fontes de Produção (PostgreSQL / MySQL / Oracle / S3 JSONL)
        │
        ├──> customers.customer_id (#1042) ──> [ FF1 Engine + KMS Key ] ──> "US-981-D"
        ├──> payments.customer_id  (#1042) ──> [ FF1 Engine + KMS Key ] ──> "US-981-D"
        └──> billing.cpf (341.890.122-10)  ──> [ Luhn / CPF Masker   ] ──> "582.109.844-32"
        │
        ▼
[ Motor Criptográfico Determinístico ]
   ├── Algoritmos: FPE FF1, AES-256-SIV, Lookup Hash, HMAC-SHA256
   ├── Provedores de Chave: AWS KMS, GCP Cloud KMS, HashiCorp Vault e K8s Secrets
   └── Garantia: Mesma chave + mesmo salt = saída byte-idêntica (100% integridade de JOINs)
        │
        ▼
Bancos de Testes & Sandboxes de IA → Preservação relacional sem expor PII real
// PRINCÍPIO DO DETERMINISMO // deslize → 
customers.customer_id (#1042) → "US-981-D"
payments.customer_id  (#1042) → "US-981-D"

Integridade de JOIN preservada a 100%.
// GESTÃO SEGURA DE CHAVES
  • • AWS KMS Key Provider nativo
  • • Provedor de Arquivos & K8s Secrets
  • • Execução 100% Thread-safe em Go
  • • Detecção automática de ciclos de cadeia
13 Algoritmos Nativos Secure Lookup, Character Mapping, Numeric Mapping, Segment Mapping, Date Shift, Full Name, Email e Nullify.
Format-Preserving Encryption Criptografia FF1 conforme NIST SP 800-38G com validação estrita de dígitos verificadores (Luhn, IBAN, CPF/CNPJ).
Static Masking Físico Transformação gravada diretamente no destino de não-produção; o dado sensível original jamais reside no ambiente de testes.
Chain de Algoritmos Possibilidade de encadear múltiplos tratamentos por campo mantendo idempotência total entre execuções.

3. Tessera Subsetter

Solicitar Documentação →

Aplicação Core · Solver Tarjan SCC em Neo4j · Web, CLI e Kubernetes

Em vez de sincronizar terabytes inteiros de produção para desenvolvimento, o Subsetter isola fatias orientadas a sementes (ex: "todas as contas ativas no Brasil criadas em 2026") e resolve recursivamente todas as chaves primárias e estrangeiras dependentes, inclusive através de grafos complexos e dependências circulares.

// ARQUITETURA DO MOTOR DE SUBSETTING (SCHEMA GRAPH & TARJAN WAVES) // deslize para ver → 
Bancos de Dados de Origem (PostgreSQL / MySQL / SQL Server / Oracle / MongoDB)
        │
        ▼
[ Neo4j Schema Graph ]  <── Mapeia FKs físicas, relações lógicas declaradas e cross-database
        │
        ▼
[ Planner de Extração ] <── Tarjan Strongly Connected Components (SCC) quebra ciclos
        │
        ▼
[ Executor em Ondas (Waves) ]
   ├── Wave 1: Tabelas raiz independentes filtradas por seed
   ├── Wave 2: Dependências filhas diretas via batch de chaves
   └── Wave 3: Resolução de tabelas com auto-relacionamentos
        │ (Opcional: Mascaramento determinístico inline durante a cópia)
        ▼
Banco de Destino (DEV / QA) → Subconjunto íntegro e referencialmente perfeito
# CI/CD CLI YAML (subsetter-job) // deslize → 
version: "1.0"
source: "postgresql://prod-ro:5432/core"
target: "postgresql://staging:5432/core_sub"
seed:
  table: "customers"
  filter: "created_at >= '2026-01-01' AND country = 'BR'"
options:
  inline_masking: true
  concurrency_waves: 4
# Kubernetes CRD (SubsetJob) // deslize → 
apiVersion: tessera.io/v1alpha1
kind: SubsetJob
metadata:
  name: nightly-qa-subset
spec:
  sourceRef: prod-db-secret
  destinationRef: qa-db-secret
  graphSolver: neo4j-cluster
  retentionPolicy: "DeleteOnSuccess"
Solver Tarjan SCC Detecta ciclos de dependência em tabelas circulares e executa a migração em ondas sequenciais e paralelas.
6 Plataformas Homologadas PostgreSQL (com leitura paralela de partições declarativas), MySQL, SQL Server, Oracle, MongoDB e Object Storage.
3 Superfícies de Engenharia Interface Web com progresso em Server-Sent Events (SSE), CLI headless para automação CI/CD e CRDs nativas do Kubernetes.
Mapeamento Lógico de Grafos Conecta relações mesmo em sistemas legados sem Foreign Keys declaradas formalmente no banco.

4. Tessera CDC & Snapshot

Solicitar Documentação →

Captura Contínua · PostgreSQL 16+ & MySQL 8+ · Eventos Canônicos JSONL para S3

Uma capacidade totalmente autônoma e independente: captura o estado inicial por snapshot consistente com isolamento MVCC e encadeia continuamente o fluxo incremental de mutações ordenado por commit, sem depender de stacks pesadas como Kafka ou Debezium.

// COORDENAÇÃO DE SNAPSHOT E STREAM DE MUTAÇÕES (BOUNDARY LSN0) // deslize para ver → 
PostgreSQL 16+ (pgoutput)  /  MySQL 8+ (binlog ROW / GTID)
                    │
                    ▼
          [ Coordenador CDC ]
          Fixa o ponto LSN0
          ┌─────────┴─────────┐
          │                   │
  [ Snapshot MVCC ]    [ Stream Incremental ]
  (Estado inicial)     (Mutações pós-LSN0)
          │                   │
          └─────────┬─────────┘
                    ▼
          [ Serializador Canônico ]
          (JSONL byte-estável, normalização de tipos e DDLs capturados)
                    │
                    ▼
   Amazon S3 / Azure Blob / Filesystem Local (Replay Determinístico)
Sem Kafka / Debezium Motor Go de baixo consumo que lê diretamente a replicação lógica nativa sem instalar extensões de terceiros no banco produtivo.
Ponto LSN0 Coordenado Elimina transações duplicadas e janelas cegas: a fronteira LSN garante transição suave do snapshot para o stream contínuo.
Captura Canônica de DDL Alteraçōes de tabela (CREATE, ALTER, DROP) são convertidas em registros estruturados para replay e versionamento em data lakes.
4 CRDs Kubernetes Controle declarativo via Kubernetes Custom Resources: CaptureSource, ReSnapshot, CaptureDestination e CaptureClass.

5. Data Environment Lifecycle (Operador Kubernetes)

Solicitar Acesso →

Visão Arquitetural · Orquestração de Ambientes Não-Produtivos Sob Demanda

A etapa final da visão Tessera é unificar a entrega de dados em um plano de controle em nuvem nativa: gerenciar o ciclo de vida completo de réplicas de banco de dados efêmeras para desenvolvedores, pipelines de CI e agentes autônomos de IA.

// PLANO DE CONTROLE DO CICLO DE VIDA DE DADOS (ROADMAP) // deslize para ver → 
Fontes de Produção → Subsetter ou CDC (com Mascaramento Determinístico)
                            │
                            ▼
           [ Réplica Intermediária Sanitizada ]
                            │
                            ▼
   [ Operador Kubernetes Tessera (Lifecycle Controller) ]
             Integrado a Block Storage / EFS / ZFS Appliance
          ┌─────────────────┼─────────────────┐
          ▼                 ▼                 ▼
   Branch de Dev       Sandbox de QA     Agente de IA Autônomo
   (Clone Efêmero)     (Snapshot Test)   (Sandbox com Rollback)
1. Provision Criação programática de réplicas leves e isoladas sob demanda para cada feature branch ou desenvolvedor.
2. Refresh Atualização contínua ou agendada com novos subsets sanitizados vindos de produção sem interferir nas réplicas ativas.
3. Snapshot Congelamento instantâneo do estado do banco antes de execuções de testes destrutivos ou migrações de schema.
4. Rollback Restauração point-in-time em segundos caso um teste falhe ou um agente autônomo corrompa a base de sandbox.
